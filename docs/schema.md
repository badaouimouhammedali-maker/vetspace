# VetSpace Database Schema

Source of truth: Flyway migrations in `backend/src/main/resources/db/migration/`.
This document describes the schema introduced by `V2__domain_schema.sql`
(`V1__init.sql` is a placeholder bootstrap table only).

Conventions used throughout:
- All primary keys are `uuid`, generated by the application (Hibernate
  `GenerationType.UUID`) with a `DEFAULT gen_random_uuid()` safety net for
  rows inserted outside the app.
- Enum columns are `varchar` + `CHECK (... IN (...))`, matching
  `@Enumerated(EnumType.STRING)` on the JPA side.
- Every foreign key column has a supporting index (or is covered by a
  primary/unique key whose leading column matches it).
- `ON DELETE` behavior is chosen per-relationship; the reasoning is
  repeated below and mirrors the SQL comments in the migration.

## Taxonomy & users

### `schools`
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| name | varchar(255) NOT NULL | |
| slug | varchar(255) NOT NULL UNIQUE | |

Since V9, schools scope **nothing**. Content is national and the access gate
looks only at study year. The table survives for two purposes: the dropdown
on the signup form, and the "Répartition par école" breakdown on the admin
overview — i.e. analytics. It is still referenced by `users.school_id` and
`notifications.school_id` (message targeting), and by nothing else.

### `users`
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| email | varchar(255) NOT NULL | unique case-insensitively via `ux_users_email_lower` on `lower(email)` |
| username | varchar(50) NOT NULL UNIQUE | |
| password_hash | varchar(255) NOT NULL | BCrypt(12) hash |
| last_name, first_name | varchar(100) NOT NULL | |
| role | varchar(20) NOT NULL CHECK | `ADMIN`, `TEACHER`, `STUDENT` |
| status | varchar(20) NOT NULL CHECK | `ACTIVE`, `DISABLED` — the account deactivation mechanism, used instead of deleting users |
| school_id | uuid NULL, FK -> schools.id | profile/analytics only — scopes no content and no access; nullable for staff not tied to one school |
| study_year | int NULL | |
| photo_url | varchar(500) NULL | |
| theme_primary, theme_secondary, theme_tertiary | varchar(20) NULL | |
| created_at, updated_at | timestamptz NOT NULL | |

**FK: `school_id` → `schools.id` ON DELETE SET NULL.** A user's identity
and history must outlive the school row; deleting a school only clears
the affiliation, never the account.

### `refresh_tokens`
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| user_id | uuid NOT NULL, FK -> users.id | |
| token_hash | varchar(255) NOT NULL UNIQUE | |
| expires_at | timestamptz NOT NULL | |

**FK: `user_id` → `users.id` ON DELETE CASCADE.** A token is meaningless

orphaned credential rows behind.

## Content

### `modules`
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| study_year | int NOT NULL | the only content scope |
| name | varchar(255) NOT NULL | |
| position | int NOT NULL | manual ordering within a study year |
| published | boolean NOT NULL DEFAULT false | |

**UNIQUE `(study_year, name)`** (`uq_modules_year_name`).

Content is **national** (V9): every school sees the same modules. A module
belongs to a study year, not to a school — `school_id` was dropped, and the
uniqueness that replaced it is what stops two "Anatomie" year 3 modules
coexisting. This is still the top of a strong-ownership chain that cascades
down to courses, questions, propositions and mindmaps.

### `courses`
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| module_id | uuid NOT NULL, FK -> modules.id | |
| name | varchar(255) NOT NULL | |
| position | int NOT NULL | |
| published | boolean NOT NULL DEFAULT false | |

**FK: `module_id` → `modules.id` ON DELETE CASCADE.** A course cannot
exist without its module.

### `source_exams`
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| label | varchar(255) NOT NULL | e.g. "Externat P6 2026" |
| year | int NOT NULL | |
| exam_type | varchar(20) NOT NULL CHECK | `ENTRAINEMENT`, `EXAMEN` |

National catalog data (V9): `school_id` was dropped along with modules'.
Questions reference an exam via `questions.source_exam_id` (ON DELETE SET
NULL), so an exam can be retired without taking its questions with it.

### `resources`
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| module_id | uuid NOT NULL, FK -> modules.id | |
| title | varchar(255) NOT NULL | |
| description | text NULL | |
| file_url | varchar(500) NOT NULL | public R2 URL; the key is `resources/{uuid}.{ext}` |
| file_type | varchar(10) NOT NULL CHECK | `PDF`, `IMAGE` — decided by magic bytes on upload |
| file_size_bytes | bigint NOT NULL CHECK > 0 | the length actually written to storage |
| position | int NOT NULL | manual ordering within a module |
| published | boolean NOT NULL DEFAULT false | |
| uploaded_by | uuid NULL, FK -> users.id | |
| created_at, updated_at | timestamptz NOT NULL | |

Indexes: `idx_resources_module_id`, `idx_resources_module_published`,
`idx_resources_published`.

The **free** half of the product (V10). Study material hangs off a module and is
readable by any authenticated student — `SubscriptionGate` is deliberately not
consulted on these reads, while the QCM bank stays behind it.

**FK: `module_id` → `modules.id` ON DELETE CASCADE.** A resource has no meaning
without its module. **FK: `uploaded_by` → `users.id` ON DELETE SET NULL** — and
hence nullable: deleting the teacher who uploaded a polycopié must not delete the
polycopié.

Deleting a row also deletes the R2 object (`ResourceService.delete`). The storage
key is recovered from `file_url` by anchoring on the `resources/` prefix rather than
on the configured base URL, so rows survive a change of public domain.

### `questions`
| Column | Type | Notes |
|---|---|---|

| course_id | uuid NOT NULL, FK -> courses.id | |

**FK: `source_exam_id` → `source_exams.id` ON DELETE SET NULL.** Losing

from.

### `mindmaps`

## Sessions & answers

### `sessions`
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| user_id | uuid NOT NULL, FK -> users.id | |
| title | varchar(255) NOT NULL | |
| session_type | varchar(20) NOT NULL CHECK | `ENTRAINEMENT`, `EXAMEN` |
| filters | jsonb NOT NULL DEFAULT `{}` | snapshot of the filters used to build the session (module/courses/sources/etc.), replayed for "repeat with same filters" |
| question_count | int NOT NULL | |
| favorite | boolean NOT NULL DEFAULT false | |
| rating | int NULL CHECK (1–5) | emoji rating |
| status | varchar(20) NOT NULL CHECK | `ACTIVE`, `SUBMITTED` |
| started_at | timestamptz NOT NULL | |
| submitted_at | timestamptz NULL | |
| total_seconds | int NOT NULL DEFAULT 0 | |
| score | numeric(5,2) NULL | |

**FK: `user_id` → `users.id` ON DELETE CASCADE.** A session is personal
study history; it's deleted with the account.

### `session_questions`
Composite PK `(session_id, question_id)` — one row per question placed
into a session.

| Column | Type | Notes |
|---|---|---|
| session_id | uuid, PK part, FK -> sessions.id | |
| question_id | uuid, PK part, FK -> questions.id | |
| position | int NOT NULL | order within the session |
| state | varchar(20) NOT NULL DEFAULT `UNANSWERED` CHECK | `UNANSWERED`, `ANSWERED`, `CONSULTED` |
| is_correct | boolean NULL | |
| seconds_spent | int NOT NULL DEFAULT 0 | |

**FK: `session_id` → `sessions.id` ON DELETE CASCADE.** Row is
meaningless without its session (and cascades transitively when the
owning user is deleted).

**FK: `question_id` → `questions.id` ON DELETE RESTRICT.** Once a
question has been placed in any session it carries historical answer
data (scores, past attempts). Hard-deleting it would corrupt that
history, so it's blocked; admins retire content via
`questions.published = false` instead of deleting it.

### `session_answers`
One row per selected proposition, scoped to a `session_questions` row.

| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| session_id, question_id | uuid NOT NULL | composite FK -> `session_questions(session_id, question_id)` |
| proposition_id | uuid NOT NULL, FK -> propositions.id | |
| selected | boolean NOT NULL | |

**FK: `(session_id, question_id)` → `session_questions(session_id,
question_id)` ON DELETE CASCADE.** Answer rows follow the lifecycle of
their `session_questions` row, which itself cascades from `sessions`.

**FK: `proposition_id` → `propositions.id` ON DELETE RESTRICT.** Defense
in depth: a proposition with recorded answers is already protected
transitively (its question can't be deleted while `session_questions`
references it), but `RESTRICT` here makes the protection explicit at the
answer layer too.

## Access

### `packs`
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| study_year | int NULL | NULL = résidanat-style pack, not scoped to a single year |
| name | varchar(255) NOT NULL | |
| academic_year | varchar(20) NOT NULL | e.g. "2026-2027" |
| price_da | int NOT NULL | price in Algerian Dinar |
| active | boolean NOT NULL DEFAULT true | |
| expires_at | timestamptz NOT NULL | fixed end date shared by all subscriptions sold from this pack |

**UNIQUE NULLS NOT DISTINCT `(study_year, academic_year)`**
(`uq_packs_year_academic`). `NULLS NOT DISTINCT` matters: Postgres treats
NULLs as distinct by default, so without it two year-less packs for the same
academic year would slip past the constraint.

Packs are national (V9) — one price list for the country, selected by study
year. `subscriptions` (below) independently protects against orphaning
access someone already paid for.

### `activation_codes`
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| pack_id | uuid NOT NULL, FK -> packs.id | |
| code_hash | varchar(255) NOT NULL UNIQUE | |
| max_uses | int NOT NULL DEFAULT 1 | |
| used_count | int NOT NULL DEFAULT 0 | |
| revoked | boolean NOT NULL DEFAULT false | |
| created_by | uuid NULL, FK -> users.id | |
| created_at | timestamptz NOT NULL | |

**FK: `pack_id` → `packs.id` ON DELETE CASCADE.** Codes belong to exactly
one pack and are worthless without it.

**FK: `created_by` → `users.id` ON DELETE SET NULL.** Keep the code (and
its redemption history) even if the admin who generated it is later
removed; only the attribution is lost.

### `subscriptions`
| Column | Type | Notes |
|---|---|---|
| id | uuid PK | |
| user_id | uuid NOT NULL, FK -> users.id | |
| pack_id | uuid NOT NULL, FK -> packs.id | |
| activation_code_id | uuid NOT NULL, FK -> activation_codes.id | |
| starts_at | timestamptz NOT NULL | |
| ends_at | timestamptz NOT NULL | |

**FK: `user_id` → `users.id` ON DELETE CASCADE.** A subscription is
personal entitlement data; it goes with the account.

**FK: `pack_id` → `packs.id` ON DELETE RESTRICT.** Blocks deleting a pack
that granted real entitlements, forcing admins to deactivate it
(`packs.active = false`) instead of silently revoking paid access via a
hard delete.

**FK: `activation_code_id` → `activation_codes.id` ON DELETE RESTRICT.**
Codes are revoked, not deleted (see `activation_codes.revoked`), so this
should never fire in practice; `RESTRICT` protects the redemption audit
trail if a code row is ever removed directly.

## Indexing summary

- Every FK column has a supporting btree index, except where it's already
  the leading column of the table's primary key (e.g. `session_id` on
  `session_questions`, `label_id` on `question_labels`, `user_id` on
  `notification_reads`) — those get an index on the *trailing* PK column
  instead, since the leading-column index doesn't serve reverse lookups.
- `users.email` is enforced case-insensitively unique via a functional
  index on `lower(email)`, independent of what the application does.
- `users.username`, `refresh_tokens.token_hash`,
  `password_reset_tokens.token_hash` and `activation_codes.code_hash` are
  plain unique constraints.
